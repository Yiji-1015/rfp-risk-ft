# 006. 문서 간 표준 문구 반복

**상태**: 수용 (데이터 결함이 아님 — 평가 보고에서 분리한다)

## 먼저, 중복이 아니다

**같은 요구사항이 두 번 들어간 것이 아니다.** 확인한 결과:

- **같은 문서 안 완전중복 0건**(유사도 ≥0.95). 추출 결함이 아니다.
  0.9대 2쌍은 실제로 다른 요구사항이다 — `CPU클러스터 서버(AI플랫폼)`와
  `CPU클러스터 서버(클라우드 관리)`처럼 대상이 다르다.
- 문서 간 85쌍은 **전부 다른 사업, 다른 `document_id`, 다른 `requirement_uid`**다.
  한국수출입은행 RFP의 감리 대응 조항과 식약처 RFP의 감리 대응 조항은 각각
  실재하는 별개 요구사항이다.

공공 RFP가 표준 문구를 공유하기 때문에 **본문이 겹치는 것**이지, 데이터가 중복된 것이 아니다.

## 누수도 아니다

처음에 이것을 "문서 단위 분할로 막히지 않는 누수"로 적었으나 과한 표현이었다.

누수는 있어선 안 될 정보가 새는 것을 뜻한다. 이건 다르다. **실제 배포에서도 새 RFP에
감리 대응과 개인정보보호법 준수가 또 나온다.** 모델이 그걸 알아보고 `통상수용`이라
답하면 그건 정답이지 부정행위가 아니다. 오염이 아니라 도메인의 성질이다.

## 관측

문자 3~4gram TF-IDF로 **다른 문서**의 최근접 요구사항을 재면:

| 유사도 | 건수 | 비율 |
|---|---:|---:|
| ≥ 0.9 | 22 | 2.1% |
| ≥ 0.8 | 50 | 4.9% |
| ≥ 0.6 | 123 | **12.0%** |
| ≥ 0.5 | 167 | 16.3% |

중앙값 0.209. 유사도 ≥0.6인 쌍 85개의 **주 라벨 일치율은 95.3%**다.
반복 조항에 일관되게 판정했다는 뜻이라 라벨 품질로는 좋은 신호다.

표준 문구 유형에 몰려 있다.

| 정본 유형 | 반복 | 비율 |
|---|---:|---:|
| 품질 | 21/64 | 32.8% |
| 프로젝트관리 | 49/151 | 32.5% |
| 제약사항 | 18/62 | 29.0% |
| 데이터 | 19/77 | 24.7% |
| 보안 | 2/88 | 2.3% |

## 실제로 남는 문제: 점수가 두 능력을 섞는다

점수 하나에 서로 다른 두 능력이 섞여 나온다.

1. **반복되는 표준 문구를 알아보는 능력**
2. **처음 보는 요구사항을 판단하는 능력**

둘 다 실전에 필요하고 둘 다 진짜 능력이다. 문제는 **섞이는 비율이 fold마다 크게
다르다**는 것이다.

| 문서 | 반복 노출률 |
|---|---:|
| mfds_drug_ai_review | 22.9% |
| korail_genai_isp_ismp | 22.4% |
| kexim_ai_platform | 19.0% |
| koen_ai_infrastructure | 17.8% |
| kangwon_land_genai | 12.0% |
| kac_ai_work_platform | 7.0% |
| incheon_airport_digital_work | 5.1% |
| defense_intelligent_platform | 4.1% |
| genai_incident_response | 1.5% |
| **ccrs_ai_platform** | **0.0%** |

`mfds`를 평가 fold로 쓰면 표본의 22.9%가 학습에서 본 문구와 겹치고, `ccrs`는 0%다.
**fold 간 점수를 나란히 놓으면 능력 차이가 아니라 구성 차이를 보게 된다.**

003(문서별 라벨 분포 편차)과 같은 종류의 문제이며, 두 효과가 겹쳐 fold 비교
가능성을 두 번 흐린다.

또한 "처음 보는 RFP에 일반화된다"는 주장을 할 때는 그 숫자의 12%가 반복 문구
인식이라는 사실을 함께 밝혀야 한다. 밝히지 않으면 주장이 실제보다 강해 보인다.

## 예시

```
sim 1.000  kexim:PMR-006  ==  mfds:PMR-001     (둘 다 통상수용)
  "추진조직 외에 본 사업을 성공적으로 수행할 수 있도록 지원 또는 자문조직의
   구성을 제시할 수 있으나, 수행 역할과 결과물이 명확해야 함"

sim 0.985  korail:DAR-009  ~  mfds:DAR-025     (둘 다 통상수용)
  같은 조항인데 글머리 기호만 다르다 (⚪/◦, ­/-)
```

## 대응

데이터를 바꾸지 않는다. **보고를 나눈다.**

점수를 셋으로 낸다.

1. 전체 점수
2. 반복 문구 제외 점수 — 처음 보는 요구사항에 대한 판단력
3. 반복 문구만의 점수 — 표준 조항 인식력

그리고 fold마다 **반복 노출률을 함께 적는다.** 그래야 fold 간 점수 차이가 능력에서
온 것인지 구성에서 온 것인지 읽을 수 있다.

## 재현

노트북 [`06_label_eda.ipynb`](../../notebooks/06_label_eda.ipynb) 마지막 셀이 계산한다.

임계값 0.6은 표준 문구를 잡되 단순히 같은 유형이라 비슷한 것은 거르는 선에서 골랐다.
0.5면 16.3%, 0.8이면 4.9%다. **결론이 임계값에 크게 좌우되므로 보고할 때 반드시 함께 적는다.**
