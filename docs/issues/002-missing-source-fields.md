# 002. 원본 결측 필드

**상태**: 수용 (원본에 없는 것을 만들어낼 수 없음)

## 관측

| 필드 | 결측 | 분포 |
|---|---:|---|
| `requirement_type` | 101건 (9.9%) | `koen_ai_infrastructure` **전건** |
| `agency` | 67건 (6.5%) | `genai_incident_response` **전건** |
| `domain` | 0건 | — |

결측이 무작위가 아니라 **문서 단위로 통째**다. 해당 RFP의 요구사항 표에 그 항목이
아예 없거나, Markdown 변환 과정에서 표 구조가 달라 추출기가 잡지 못한 경우다.

## 영향

- 문서 단위 결측이라 **결측 자체가 문서 식별자**가 된다. `requirement_type`이 비었다는
  사실만으로 `koen_ai_infrastructure`임을 알 수 있다. 특징으로 쓰면 누수다.
- 결측을 최빈값 등으로 채우면 그 문서 전체가 한 값으로 쏠려 왜곡이 더 커진다.

## 대응

- 데이터셋에는 **비운 채로 둔다.** 로더가 `NULLABLE_FIELDS`로 허용하되 결측 수를
  메타에 세어 남기므로, 분석에서 눈에 띈다.
- 특징으로 쓸 때는 **결측 여부를 파생 특징으로 만들지 않는다.** 문서 식별자가 된다.
- `requirement_type` 결측 101건은 [001](001-requirement-type-fragmentation.md)의 정규화에서
  **접두어로 대체**했다(`requirement_type_source == "prefix"`). 해당 문서는 접두어 충돌이
  없어 안전하다. 원본 필드는 여전히 비어 있으므로 이 이슈 자체는 남는다.
- `agency`는 문서 ID에서 유추해 채울 수 있지만(침해대응체계 RFP의 발주기관은 확인
  가능), 원본에 없는 값을 데이터셋에 써넣는 것은 추출 결과가 아니라 주석이다.
  필요하면 별도 문서 메타 테이블로 분리한다.
