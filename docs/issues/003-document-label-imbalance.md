# 003. 문서별 라벨 분포 편차

**상태**: 수용 (데이터 결함이 아님 — 평가 설계에서 다룬다)

## 관측

| 문서 | 건수 | 통상수용 | 다수 클래스 기준선 |
|---|---:|---:|---:|
| ccrs_ai_platform | 95 | 28.4% | 36.8% |
| genai_incident_response | 67 | 29.9% | 37.3% |
| defense_intelligent_platform | 169 | 32.5% | 34.3% |
| kangwon_land_genai | 50 | 40.0% | 46.0% |
| kac_ai_work_platform | 86 | 41.9% | 40.7% |
| incheon_airport_digital_work | 78 | 46.2% | 46.2% |
| kexim_ai_platform | 137 | 48.2% | 48.2% |
| mfds_drug_ai_review | 192 | 71.9% | 71.4% |
| korail_genai_isp_ismp | 49 | 75.5% | 75.5% |
| koen_ai_infrastructure | 101 | 79.2% | 79.2% |

통상수용 비율 **28.4% ~ 79.2%**(2.8배), 문서 규모 **49 ~ 192건**(3.9배).

## 이것은 결함이 아니다

**분포 차이는 사실이다.** `koen_ai_infrastructure`는 인프라 증설 사업이라 표준 문구가
많고 통상수용이 실제로 많다. `ccrs_ai_platform`은 플랫폼 신규 구축이라 원가가 붙는
요구사항이 많다. **어떤 RFP는 실제로 더 쉽다.** 데이터를 고쳐서 없앨 대상이 아니다.

**건수 차이도 학습 입력이 아니다.** 학습 입력은 요구사항 원문이다. "이 문서에 192건이
있다"는 정보는 모델에 들어가지 않는다.

## 그래서 실제로 남는 문제

### 1. fold 간 절대 점수를 비교할 수 없다

`koen_ai_infrastructure`를 평가에 쓰면 통상수용만 찍어도 79.2%다.
`defense_intelligent_platform`에서는 34.3%가 그 수준이다. 같은 모델이 fold에 따라
두 배 넘게 다른 점수를 낸다. **성능 차이가 모델이 아니라 분할에서 온다.**

→ **fold별 다수 클래스 기준선을 항상 함께 보고한다.** 절대 점수만 쓰지 않는다.
   노트북 `06_label_eda.ipynb`가 이 표를 매번 계산한다.
   기준선 대비 개선폭(예: 정확도 − 기준선)으로 비교하는 편이 안전하다.

### 2. 집계 방식을 골라야 한다

fold 단순 평균이면 49건짜리 fold가 192건짜리와 같은 무게를 갖는데 분산은 훨씬 크다.
건수 가중이면 큰 문서 세 개(mfds·defense·kexim, 전체의 48.6%)가 결과를 지배한다.

→ **둘 다 보고한다.** 하나만 쓰면 어느 쪽이든 오해를 만든다.

### 3. 학습 구성이 큰 문서 쪽으로 기운다

특징이 아니라 표본 수의 문제다. 모델이 mfds 문체를 korail보다 4배 많이 본다.

→ fold 배정 시 통상수용 비율로 층화해 fold 간 분포를 맞추는 것을 검토한다.
   다만 문서가 10개뿐이라 층화 여지가 좁다.

## 정리

**데이터를 바꾸는 대응은 없다.** 전부 평가 설계와 보고 방식의 문제다.
이 이슈는 "고쳐야 할 결함"이 아니라 **"실험 설계에서 반드시 다뤄야 할 제약"**으로 읽는다.
