# RFP 견적·계약 검토 지원

> 제안 실무에서 출발해, 문서 추출·라벨링·모델 평가까지 연결한 개인 프로젝트입니다.
> 모델이 입찰 여부를 결정하기보다, 먼저 읽을 조항을 좁히는 데 목적을 두었습니다.

| 항목 | 내용 |

| 작성자 | 윤이지 |
| 기간 | 2026.08~진행 중 |
| 형태 | 개인 프로젝트 |

### 시작한 이유

RFP를 읽고 제안서를 작성하는 것이 제 업무입니다. 수십~수백 개의 요구사항을 읽으며, 입찰에 참여할지 빠르게 판단하기 어려웠습니다. 무심코 넘긴 조건이 특정 공급자에게 유리한 제약일 수도 있었습니다.

모든 조항을 같은 무게로 읽는 대신, 검토 순서를 정하고 싶었습니다. 일반적인 수행 조건과 추가 원가, 계약 전 확인 사항을 구분했습니다. 이를 먼저 분류해 주는 도구를 개인 프로젝트로 만들었습니다.

### 무엇을 만들었나

**문서를 읽을 수 있는 데이터로 바꾸고, 판단 기준과 평가 절차를 함께 만들었습니다.**

1. Markdown·HWP·XLSX에서 요구사항을 추출하는 파서를 만들었습니다.
2. 예시 인출·배치 호출·재시도·비용 추적을 갖춘 라벨링을 구현했습니다.
3. 처음 보는 문서에서 모델을 비교하는 평가 체계를 만들었습니다.
4. 전통 ML·인코더와 Qwen 7B LoRA 파인튜닝을 비교했습니다.
5. 오답과 원문 근거를 검토할 수 있는 분석 도구를 만들었습니다.

흐름: **RFP 수집·추출 → 데이터 검증 → 라벨링 → 학습·평가 → 오답 검토**

## 2. 첫 번째 문제: 무엇을 ‘위험’이라고 부를 것인가

처음에는 조항의 위험도를 바로 분류하려고 했습니다. 하지만 초기 파일럿 40건에서 계약·질의검토가 80%를 차지했습니다. 기술적으로 어렵거나 규모가 큰 요구를 계약 위험과 혼동하고 있었습니다.

그래서 질문을 ‘위험한가’에서 ‘어떻게 수용할 것인가’로 바꿨습니다. 추가 원가를 계산할 수 있는지, 입찰 전에 확인할 조건이 있는지 나눴습니다. 난이도는 별도의 보조 축으로 분리했습니다.

| 주 라벨 | 판단 기준 |
|---|---|
| 통상수용 | 기본 수행팀이 별도 원가나 협상 없이 처리할 수 있습니다. |
| 견적반영 | 추가 원가가 있지만, 수행 범위를 견적에 반영할 수 있습니다. |
| 계약·질의검토 | 안전한 수용을 위해 입찰 전에 확인해야 할 조건이 있습니다. |

여기서 `blocker`는 단순히 비용이 든다는 뜻이 아닙니다. 사전 확인이 필요한 조건을 가리키도록 정의했습니다. 범위·책임, 검수·성능기준, 기술실현성, 라이선스·공급, 공급자종속으로 나눴습니다.

판단 주체도 고정했습니다. ‘기본적인 LLM·RAG 구축 역량이 있는 팀’을 기준으로 삼았습니다. 특정 기관의 업무 지식까지 가진 전문가로 가정하지 않았습니다.

**복잡한 기술이라는 이유만으로 계약 위험을 높이지 않는 것이 핵심이었습니다.** 특정 공급자에게 유리할 가능성도 검토 대상으로 삼았습니다. 다만 해당 업체가 내정됐다는 사실까지 모델이 단정하지 않게 했습니다.

## 3. 정확한 라벨링을 위해 시도한 것

사람이 전수 정답을 만드는 대신 Claude로 라벨링했습니다. 따라서 일관성과 실무 타당성을 따로 확인해야 했습니다. 반복해서 같은 답이 나와도, 그 답이 실무적으로 옳다는 뜻은 아니었습니다.

### 3.1 예시를 많이 주기보다, 어떤 예시를 줄지 바꿨습니다

| 시도 | 확인한 문제 또는 결과 | 이후 판단 |
|---|---|---|
| Gemini zero-shot·유사도 few-shot 비교 | 259건의 두 방식 일치율은 약 70%였습니다. few-shot의 견적반영 비중은 68.7%였습니다. | 비슷한 예시만 넣으면 한 라벨에 쏠릴 수 있었습니다. |
| 라벨별 1:1:1 층화 few-shot | 각 라벨의 예시를 하나씩 넣도록 바꿨습니다. | 예시 구성을 통제하는 기본 전략으로 채택했습니다. |
| Claude로 라벨링 모델 통일 | 모델이 다른 실행끼리 직접 비교하는 문제를 줄였습니다. | 프롬프트·인출 조건을 실행 기록에 남겼습니다. |
| 같은 입력을 세 번 반복 | 40건에서 주 라벨 전원 일치는 90.0%에서 92.5%였습니다. | 작은 표본에서 한 건 차이였으며, 정확도 향상으로 표현하지 않았습니다. |
| 보조 축의 반복 일관성 확인 | 구축 난이도는 개선됐지만 blocker 일관성은 낮아졌습니다. | few-shot이 모든 판단 축을 개선한다고 보지 않았습니다. |
| 고정 예시와 동적 예시 비교 | 층화·고정 방식의 라벨 일치율은 76.9%였습니다. | 예시가 판단 기준 자체를 움직일 수 있음을 확인했습니다. |

### 3.2 판단 기준을 검토하고, 앵커를 고정했습니다

실무자로서 12건을 직접 검토했습니다. 비용 부담과 계약 조건을 나누는 기준을 다듬었습니다. 그 판단을 프롬프트의 페르소나와 blocker 정의에 반영했습니다.

앵커 후보에는 세 번의 반복 판정이 일치하는지 확인했습니다. 초기 스크리닝 통과율은 81%였습니다. 이후 주 실험의 예시 풀을 100건으로 동결했습니다.

중간에는 새 라벨링 결과를 되먹여 앵커를 192건으로 늘렸습니다. 그러나 실행 순서에 따라 이후 입력의 예시가 달라졌습니다. 검증 수준도 달라져, 누적 확장을 되돌리고 고정 풀을 사용했습니다.

대상 조항과 같은 문서의 앵커는 인출하지 않았습니다. 동결 앵커 100건은 검증·평가에서도 제외했습니다. 라벨 생성 때 예시로 쓰였던 조항을 새 사례처럼 채점하지 않기 위해서였습니다.

### 3.3 최근 프롬프트 세 버전: v5·v6·v7

프롬프트 버전과 데이터셋 버전은 구분했습니다. 프롬프트 v5로 만든 데이터가 데이터셋 v4와 v5에 들어갑니다. 아래 점수는 각 데이터셋의 라벨을 학습·평가한 결과입니다.

| 구분 | 프롬프트 v5 | 프롬프트 v6 계열의 최종 v6c | 프롬프트 v7 |
|---|---|---|---|
| 해결하려던 문제 | 난이도·비용·계약 위험의 혼동 | 사전 확인 사항을 지나치게 넓게 잡는 문제 | 실무 검토에서 발견한 구체적인 과다 판정 |
| 핵심 변경 | blocker → 추가 원가 → 통상수용 순으로 판정 | 원가로 감당할 수 없는 손해·이행 불능 중심으로 blocker 축소 | v5에 과다 판정 방지 규칙 5항 추가 |
| 예시 조건 | 층화 few-shot, 동결 앵커 100건 | zero-shot | 층화 few-shot, 충돌 예시 9건을 뺀 앵커 91건 |
| 추가 지시 | 표준 문구·컨설팅 보정, 난이도 축 분리 | 근거 원문 인용, 공급자 제약 설명 보강 | 수량·성능, 설정값·열린 범위 등을 구체적으로 구분 |
| 비교 데이터 | v5, 1,445건 | v6, 같은 요구사항 1,445건 | v7, 같은 요구사항 1,445건 |
| 계약·질의검토 비중 | 25.1% | 12.9% | 19.6% |
| TF-IDF fold 평균 macro F1 | 0.6395 | 0.5991 | 0.6040 |
| 판단 | 주 데이터셋으로 유지했습니다. | 주 비교 조건으로 채택하지 않았습니다. | 실무 기준 변경의 효과를 분석하는 데이터로 보존했습니다. |

#### v5: 판단 순서와 예외를 명확히 했습니다

우선 blocker를 확인하고, 없으면 추가 원가를 확인했습니다. ‘무중단 운영’ 같은 표준 문구를 곧바로 위험으로 읽지 않게 했습니다. 기술명만 등장하는 컨설팅 조항도 구현 책임과 구분했습니다.

이 조건으로 초기 1,024건을 라벨링했습니다. 이후 문서 3개를 같은 조건으로 추가했습니다. 확장된 1,445건이 현재 주 비교 데이터셋 v5입니다.

#### v6: 위험의 정의를 좁혀 봤습니다

‘확인하면 좋은 조건’과 ‘반드시 바로잡아야 할 조건’을 구분했습니다. 견적으로 감당 가능한 부담은 비용으로 분류하도록 했습니다. 판단 근거를 원문에서 인용하는 지시도 추가했습니다.

중간 버전 v6b에서는 조건절 한 줄이 판정을 크게 바꿨습니다. 견적반영 127건이 통상수용으로 이동하는 회귀를 확인했습니다. v6c에서 해당 조건을 제거해 보정했습니다.

최종 v6c 구성에서도 계약 라벨이 크게 줄었습니다. TF-IDF 점수는 0.5991로 주 기준선보다 낮았습니다. 다만 규칙과 예시 제공 방식을 함께 바꿔 원인을 분리할 수는 없습니다.

#### v7: 실제 오판 유형을 규칙으로 옮겼습니다

경계 혼동 127건을 정성 검토하고, 직접 판정한 27건을 참고했습니다. v5의 기본 구조를 유지하며 다음 다섯 가지를 보정했습니다.

1. **수량과 성능 목표를 구분했습니다.** 모델 개수와 합격을 가르는 정확도 목표를 다르게 봤습니다.
2. **설정값 협의와 열린 구현 범위를 구분했습니다.** 보관 기간 협의를 기능 범위 미정과 동일하게 읽지 않게 했습니다.
3. **일반 사양·인력·보안 조건을 원가와 구분해 봤습니다.** 특정 제품 지정이나 공급자 제한은 별도 검토 대상으로 남겼습니다.
4. **긴 기능 목록과 계약 위험을 구분했습니다.** 복잡해도 항목별 원가를 계산할 수 있는지 먼저 보게 했습니다.
5. **여전히 확인이 필요한 조건을 명시했습니다.** 조달 불확실성·외부 승인·무제한 의무 등을 유지했습니다.

v7은 전수 신규 라벨링이 아닙니다. 통상수용을 제외한 695건을 대상으로 692건을 회수했습니다. 실패한 3건과 기존 통상수용 750건은 v5 라벨을 유지했습니다.

통상수용 유지 가정은 별도 50건으로 확인했습니다. 49건이 유지됐지만, 한 건은 상향됐습니다. 따라서 ‘보정은 항상 하향만 한다’고 일반화하지 않았습니다.

직접 검토한 사례 중 비교 가능한 26건의 일치가 11건에서 18건으로 늘었습니다. 그러나 TF-IDF 점수는 0.6040으로 내려갔습니다. 이 표본에서의 개선을 전체 라벨 정확도 향상으로 확대하지 않았습니다.

### 3.4 라벨링을 반복 실행할 수 있도록 만들었습니다

| 구현 | 필요했던 이유 |
|---|---|
| 구조화 출력·스키마 검증 | 응답을 받았다는 사실과 유효한 라벨 확보를 구분했습니다. |
| 주 라벨·보조 축 규칙 대조 | blocker와 원가근거가 주 라벨과 맞는지 검사했습니다. |
| 동일 조건 재시도 | 실패한 건만 다른 프롬프트로 처리하지 않도록 했습니다. |
| 배치 API·사용량 기록 | 전수 라벨링의 실행 비용과 회수 상태를 관리했습니다. |
| 전략별 프롬프트 캐시 | 고정 블록을 재사용하되 동적 예시와 구분했습니다. |
| 실행 manifest | 모델·프롬프트·앵커·입력과 결과의 출처를 남겼습니다. |

캐시는 고정 예시 전략에 맞춰 별도로 설계했습니다. 입력마다 달라지는 층화 예시까지 고정 캐시처럼 취급하지 않았습니다. 작은 배치의 캐시 효율이 큰 배치에서도 유지되지 않는 점도 기록했습니다.

Solar Pro로 라벨링 모델을 바꾸는 실험도 했습니다. 단순 일치율 외에 규칙 준수와 근거 인용을 비교했습니다. 해당 파일럿에서는 지시 이행이 부족해 대체 모델로 채택하지 않았습니다.

## 4. 라벨을 바꿀 때, 전처리와 모델은 어떻게 연결했나

프롬프트마다 유리한 전처리를 새로 붙이지는 않았습니다. 공통 입력과 평가 절차를 유지하며 라벨 조건을 비교했습니다. 입력 표현·모델 변경은 별도의 실험으로 나눴습니다.

### 4.1 공통 전처리: 원문의 의미를 보존했습니다

| 처리 | 구현과 판단 |
|---|---|
| 표 파싱 | 초기 10문서는 Markdown 표에서 읽었습니다. 추가 문서는 HWP·XLSX에서 직접 추출했습니다. |
| 행 단위 고정 | 요구사항 ID 하나를 한 행으로 유지했습니다. 불릿마다 별도 표본을 만들지 않았습니다. |
| 공통 정규화 | HTML 문자, Unicode, 줄바꿈과 공백을 정리했습니다. |
| 불릿 정규화 | 줄 시작 기호를 통일하고 숫자·단위·문장 내부 하이픈은 보존했습니다. |
| 모델 입력 | 요구사항명과 정규화 본문을 함께 사용했습니다. |
| 유형 정규화 | 서로 다른 유형 표기 60종을 12종으로 정리했습니다. 분석용 정리와 모델 특징 실험을 구분했습니다. |
| 동결·출처 보존 | SHA-256과 UID·스키마 검증으로 조용한 데이터 변경을 막았습니다. |

요약 생성으로 중요한 조건을 지우지 않도록 했습니다. 원문과 정규화된 모델 입력을 따로 보관했습니다. 모델 입력을 바꿔도 원문을 다시 대조할 수 있게 했습니다.

### 4.2 전처리·특징 실험: 더 많이 넣는 것이 답은 아니었습니다

| 시도 | 확인하려던 가설 | 결과와 선택 |
|---|---|---|
| 요구사항명·불릿 정규화 | 제목과 정돈된 목록이 분류에 도움이 되는지 확인했습니다. | 초기 문서 기준 입력을 정리하고 v4 조건으로 고정했습니다. |
| 단어·문자 n-gram 결합 | 한국어 표기 차이와 단어 단위 신호를 함께 보려 했습니다. | word+char TF-IDF를 주 기준선으로 사용했습니다. |
| 유형 one-hot·유형 가중치 | 요구사항 종류가 검토 조치를 설명하는지 확인했습니다. | 기준선 이상의 안정적인 이득을 얻지 못했습니다. |
| 글자 수·숫자 개수 | 규모와 구체성을 간단한 수치로 표현했습니다. | 단순 길이·숫자만으로 경계를 설명하기 어려웠습니다. |
| 한국어 의존구문 | 의무·행위·대상의 문장 구조를 활용했습니다. | 추가 처리 대비 성능 이득이 없어 채택하지 않았습니다. |
| E5 임베딩·TF-IDF 결합 | 어휘가 달라도 비슷한 뜻을 잡으려 했습니다. | v5 결합 점수는 0.619로 기준선보다 낮았습니다. |
| 주체·어미·조사 마스킹 | 문서 양식을 외워서 맞히는지 확인했습니다. | v4의 개선 신호가 v5에서 재현되지 않았습니다. |
| 군집·문서 간 분포 특징 | 유사 조항의 분포가 일반성을 설명하는지 확인했습니다. | 예측 특징으로는 기각하고 오답 진단에 활용했습니다. |
| 긴 입력·BigBird | 입력 절단이 오답의 주원인인지 확인했습니다. | 기존 실험에서 기대한 개선을 얻지 못했습니다. |

마스킹 실패가 모든 양식 편향의 부재를 증명하는 것은 아닙니다. 시도한 제거 규칙에서 안정적인 이득이 없었다고 해석했습니다. 군집도 예측에 도움되지 않았지만, 오류를 이해하는 데는 유용했습니다.

### 4.3 모델 실험: 질문별로 범위를 넓혔습니다

초기에는 단순한 모델을 충분히 비교했습니다. 그다음 표현·용량·학습 방식·결정 구조를 바꿨습니다. 아래는 서로 다른 실행을 모델 계열과 목적별로 묶은 표입니다.

| 실험 묶음 | 실제 시도 | 결과와 다음 판단 |
|---|---|---|
| 기본 선형·확률 모델 | Logistic Regression, LinearSVC, ComplementNB, Elastic-net | 문자 TF-IDF와 클래스 가중치가 강한 기준선이 됐습니다. |
| 표현·차원 축소 | E5, SVD+Logistic, TF-IDF+E5 | 표현을 복잡하게 바꿔도 안정적인 우위는 없었습니다. |
| 비선형 모델 | SVD+XGBoost, 원 특징 XGBoost, 용량 확대 | v5에서 0.595, 용량 확대 시 0.561로 낮아졌습니다. |
| 텍스트 전용 대안 | fastText, NB-SVM | 기존 비교에서 기준선을 넘지 못했습니다. |
| 하이퍼파라미터 선택 | 검증 문서에서 설정·가중치 선택 | 더 넓은 탐색이 자동으로 일반화 개선을 만들지는 않았습니다. |
| 인코더 파인튜닝 | KLUE RoBERTa small·base·large, KoELECTRA, BigBird | v5 base·large는 복수 seed로 확인했습니다. 단독보다 결합이 유효했습니다. |
| 결정 구조 | OvR, OvO, 계약 우선 캐스케이드 | 분류 순서를 바꾸는 것만으로 경계가 풀리지 않았습니다. |
| 학습 타깃·가중치 | 보조 헤드, 소프트 라벨, 안정 라벨만 학습, 일치도 가중치 | 기존 비교에서 주 실험으로 채택할 개선을 얻지 못했습니다. |
| 앙상블 | 동일 계열 soft voting, 다른 계열 다수결, 멤버·조합 확대 | TF-IDF와 base·large를 섞는 구성이 유효했습니다. |
| LLM 재판정 | Solar 이견 재판정, 문서 맥락 카드 | 기존 파일럿에서 뚜렷한 채택 근거를 얻지 못했습니다. |
| sLLM | Qwen2.5-7B-Instruct의 양자화 없는 LoRA | v5 단독 0.644, v7 단독 0.665였습니다. 아래 완료 결과에 정리했습니다. |

초기 10문서 실험과 이후 13문서 실험은 평가 대상이 다릅니다. 위 표는 시도한 범위를 정리한 것이며, 모두 같은 데이터의 순위표는 아닙니다. 같은 조건의 수치 비교는 아래 v5 표로 한정했습니다.

### 4.4 v5에서 같은 조건으로 비교한 결과

평가는 13문서 LODO로 진행했습니다. 각 fold는 학습 11문서·검증 1문서·평가 1문서로 나눴습니다. 앵커를 제외한 1,345건을 각자의 평가 fold에서 한 번씩 채점했습니다.

macro F1은 세 라벨의 F1을 같은 비중으로 평균한 값입니다. 아래 주 지표는 문서별 macro F1의 단순 평균입니다. 정답 기준은 전문가 전수 확정값이 아니라 동결된 Claude 생성 라벨입니다.

| 구성 | fold 평균 macro F1 | 전체 오답 | 견적↔계약 경계 혼동 |
|---|---:|---:|---:|
| word+char TF-IDF | 0.640 | 401 | 127 |
| TF-IDF+E5 | 0.619 | 424 | 136 |
| TF-IDF 계열 soft voting | 0.632 | 410 | 126 |
| RoBERTa-base, seed 7 | 0.634 | 391 | 125 |
| RoBERTa-large, seed 42 | 0.655 | 379 | 134 |
| TF-IDF+base s7+large s42 다수결 | **0.671** | **356** | **117** |

앙상블은 기준선보다 오답을 45건 줄였습니다. 그중 견적·계약 경계 혼동 감소는 10건이었습니다. 점수가 올라도 가장 어려운 경계가 크게 남는다는 점을 함께 봤습니다.

base·large의 seed 조합 9쌍도 확인했습니다. 앙상블 점수는 0.666~0.683, 평균은 0.6745였습니다. 0.671은 지정 조합의 점수이며, 모든 조합 중 최고값은 아닙니다.

large 단독의 3개 seed 평균은 0.652였습니다. 기준선보다 높았지만, 차이는 약 0.012였습니다. 모델 크기만 키워 확실히 해결했다고 설명하지 않았습니다.

## 5. v7에서는 왜 라벨 검토와 모델 점수가 엇갈렸나

v7은 검토한 표본에서 실무자 판단과 더 많이 일치했습니다. 그러나 각 데이터셋의 라벨을 맞히는 모델 점수는 내려갔습니다. 라벨 타당성과 모델의 라벨 재현도를 따로 봐야 했습니다.

| 같은 모델 구성 | v5 기준 | v7 기준 |
|---|---:|---:|
| word+char TF-IDF | 0.6395 | 0.6040 |
| RoBERTa-base, seed 7 | 0.634 | 0.622 |
| RoBERTa-large, seed 42 | 0.655 | 0.640 |
| TF-IDF+base s7+large s42 | 0.671 | 0.652 |

두 열은 입력 조항은 같지만 정답 라벨이 다릅니다. 따라서 동일 시험에서 모델 성능만 떨어진 비교는 아닙니다. 어떤 판단을 학습하도록 정의했는지가 함께 달라진 결과입니다.

v7에서는 계약 라벨 비중과 해당 클래스의 F1이 함께 내려갔습니다. 통상수용을 더 잘 맞혀도 macro F1은 낮아질 수 있었습니다. 다만 클래스 비중 감소만으로 점수 하락이 필연적인 것은 아닙니다.

TF-IDF보다 인코더의 하락 폭은 작았습니다. 이 결과를 의미 구분을 읽는 모델의 상대적 가능성으로 해석했습니다. v7 인코더는 seed 하나씩이므로 확정적인 일반화는 피했습니다.

## 6. 남은 오답을 어떻게 이해했나

모델 변경으로 해결되지 않는 견적·계약 경계를 다시 읽었습니다. 문서 밖 조달 지식, 수행사 역량, 판단 기준의 차이가 섞여 있었습니다. 모든 오답을 하나의 원인으로 설명하지는 않았습니다.

E5로 다른 문서의 비슷한 조항 다섯 개를 찾아봤습니다. 기준선이 맞힌 조항의 이웃 라벨 일치율은 약 79%였습니다. 경계 오답에서는 약 26%에 그쳤습니다.

이는 비슷한 표현 주변에서도 라벨이 일관되지 않은 자리라는 관측입니다. 어떤 텍스트 모델도 해결할 수 없다는 증명은 아닙니다. 원문 외 정보나 판단 규칙을 더 살펴볼 근거로 활용했습니다.

사업비·기간·망 환경 등을 담은 문서 맥락 카드도 시험했습니다. 해당 파일럿에서는 경계 혼동 개선이 확인되지 않았습니다. Qwen 7B LoRA를 학습하고 경계 오답의 이동을 분석했습니다. 이후 입력 절단과 판단 기준의 차이도 확인했습니다.

## 7. 결과보다 강조하고 싶은 일하는 방식

### 작은 점수 차이를 곧바로 성과로 적지 않았습니다

v4에서 좋아 보였던 마스킹 효과가 v5에서는 재현되지 않았습니다. 이때 fold별 차이의 변동을 다시 계산했습니다. 이후 약 0.016을 후속 실험의 효과 크기 선별 기준으로 사용했습니다.

이 기준은 처음부터 알고 있던 상수가 아닙니다. 9월 7일의 재검증 과정에서 도출했습니다. 모든 실험에 통하는 통계적 유의성 경계로 확대하지 않았습니다.

### 모델을 더 바꾸기 전에 데이터 부족을 확인했습니다

학습 문서 수를 늘렸을 때의 점수 변화를 살펴봤습니다. 개선 여지가 남아 있어 문서 3개를 추가했습니다. TF-IDF fold 평균은 0.6144에서 0.6395로 높아졌습니다.

문서 추가로 학습·평가 모집단도 바뀌었습니다. 따라서 같은 평가셋에서 얻은 순수 학습량 효과라고 단정하지 않았습니다. 모델 변경에만 매달리지 않고 데이터를 늘린 판단을 성과로 남겼습니다.

### 틀렸던 해석도 지우지 않고 정정했습니다

문서 간 반복 문구를 처음에는 누수로 의심했습니다. 이후 실제 사용에서도 등장하는 공통 문구라는 점을 검토했습니다. 분할 문제와 반복 표현 자체를 구분해 기록을 정정했습니다.

앵커 누적 확장과 마스킹 해석도 같은 방식으로 수정했습니다. 실패한 실행과 당시 판단을 남기고, 수정 이유를 덧붙였습니다. **다음 실험이 이전 실패의 근거 위에서 이어지도록 했습니다.**

라벨 기준과 예시 구성을 반복해서 검토했습니다. 전처리·모델·결정 구조를 바꾸며 개선 여부를 확인했습니다. 데이터 확충과 다른 계열의 앙상블에서 주요 개선을 얻었습니다.

**이 프로젝트의 결과물은 분류기와 함께, 판단을 검증하는 절차입니다.** 실무자의 입찰 결정을 대신하는 서비스로 배포하지는 않았습니다. 무엇을 먼저 읽고 어디서 판단을 유보할지 정리한 개인 연구입니다.

## 9. Qwen 7B LoRA 파인튜닝과 오답 진단

Qwen2.5-7B-Instruct를 v5·v7로 각각 학습했습니다. 실제 실행은 4bit QLoRA가 아닌 양자화 없는 LoRA였습니다. 두 실행 모두 seed 42와 같은 system 지시를 사용했습니다.

| 구성 | v5 fold 평균 | v5 경계 혼동 | v7 fold 평균 | v7 경계 혼동 |
|---|---:|---:|---:|---:|
| TF-IDF | 0.640 | 127 | 0.604 | 107 |
| RoBERTa-large | 0.655 | 134 | 0.640 | 96 |
| Qwen LoRA | 0.644 | 128 | 0.665 | 110 |
| 기존 TF-IDF+base+large | 0.671 | 117 | 0.652 | 102 |
| TF-IDF+large+Qwen | 0.683 | 111 | 0.662 | 97 |

v5에서는 Qwen을 섞어 점수가 약 0.011 올랐습니다. 후속 실험의 선별 기준 0.016에는 못 미쳤습니다. 기존 주 구성을 유지하고, 경계 혼동 6건 감소를 보완 효과로 기록했습니다.

v7에서는 Qwen 단독이 large보다 약 0.025 높았습니다. 그러나 두 모델의 오답은 338건으로 같았습니다. 경계 혼동은 96건에서 110건으로 늘어 점수만으로 개선을 설명하지 않았습니다.

라벨에 따라 모델의 상대적인 강점이 달랐습니다. 다만 seed는 하나이며, v5·v7의 정답 자체도 다릅니다. 이 결과를 전체 라벨 정확도나 실무 성능의 확정 증거로 삼지 않았습니다.

학습용 system 지시는 두 버전에서 같았습니다. v7 라벨링 프롬프트 전체를 준 실험은 아닙니다. 따라서 프롬프트 교체 효과와 sLLM의 상식 효과를 분리해 주장하지 않았습니다.

### 라벨 토큰만 학습하고 후보의 로그확률을 비교했습니다

LoRA r=16을 선형층에 적용했습니다. 프롬프트를 loss에서 제외하고 라벨과 EOS 토큰만 학습했습니다. 클래스 가중치도 반영했습니다.

세 후보 라벨의 로그확률 합으로 판정했습니다. 자유 생성 결과를 파싱하는 방식은 쓰지 않았습니다. 각 fold의 검증 F1이 가장 높은 epoch를 평가했습니다.

v5·v7 각각 13문서 LODO를 완료했습니다. 버전별 평가 대상은 동결 앵커를 제외한 1,345건입니다. 원격 결과를 회수해 정답·예측과 점수를 다시 검증했습니다.

### 큰 모델의 실패를 입력과 판단 기준으로 나눴습니다

v5 앙상블은 기존 경계 오답 20건을 맞혔습니다. 하지만 새 경계 오답도 17건 생겼습니다. 일부 정답은 다른 모델의 투표에 밀렸습니다.

Qwen 토크나이저로 실제 입력 범위를 확인했습니다. 평가 조항 205건은 512토큰을 넘었습니다. 정답률 90%와 5년 부품공급 조건이 빠진 사례를 찾았습니다.

반면 70토큰의 성능 조항도 틀렸습니다. 입력 누락만으로 모든 오답을 설명할 수 없었습니다. 라벨 기준과 실무자 판단이 다른 사례도 구분했습니다.

**모델 크기뿐 아니라, 모델이 실제로 읽은 근거까지 검증했습니다.** 전체 입력을 주면 개선된다는 실험은 아직 하지 않았습니다. 누락 확인과 성능 개선을 구분해 기록했습니다.

Qwen2.5-7B-Instruct를 LoRA로 파인튜닝했습니다. 라벨 토큰 학습과 로그확률 판정을 구현했습니다. v5·v7 각각 13문서 LODO로 검증했습니다.

v7 단독 macro F1은 0.665를 기록했습니다. 점수와 별개로 경계 오답은 늘었습니다. 입력 절단과 실무 판단 차이까지 분석해 한계를 설명했습니다.
