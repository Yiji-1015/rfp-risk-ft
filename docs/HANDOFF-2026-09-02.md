## 2. 집에서 할 일 — 순서대로

gcube 콘솔에 브라우저로 붙어 터미널을 연다. `cd rfp-risk-ft` 후:

**① 다 끝났는지 확인** — 10이면 완료다(오늘 로컬 3줄 + 낮에 돌린 base 1줄 + 오늘 저녁 6줄).

```bash
grep -c "^{" reports/current/v4/finetune_runs.jsonl
```

**② 요약만 훑기**

```bash
grep "마스킹\|fold 평균\|통합 OOF" run.log
```

**③ 결과 통째로 복사** — 이게 본체다. 어딘가에 붙여 보관한다.

```bash
cat reports/current/v4/finetune_runs.jsonl
```

**④ 에러가 났는지 확인** (특히 6번 large는 VRAM이 빠듯하다)


**⑤ ③을 복사해 둔 것을 확인한 뒤에** 워크로드를 내린다.

> ⚠️ 개인 저장소를 안 붙였다. 워크로드를 내리면 **컨테이너 파일시스템이 통째로 사라진다.**
> `finetune_runs.jsonl` 내용을 손에 넣기 전에는 절대 내리지 말 것. 요금은 시간당
> 252~360원이라 밤새 켜두면 4,000원 안팎이 나간다.

## 3. 숫자를 어떻게 읽나

각 실행 끝에 `fold 평균 평가 macro F1`과 `통합 OOF macro F1`, 라벨별 F1이 찍힌다.
비교 대상은 **같은 924건, 같은 8/1/1 LODO**에서 나온 아래 값들이다.

| 기준선 (v4, fold 평균) | macro F1 |
|---|---:|
| Dummy(최빈) | 0.219 |
| char TF-IDF + balanced | 0.608 |
| **word+char TF-IDF + balanced** | **0.614** |
| 파인튜닝 base seed 42 (낮에 돌린 것) | 0.602 |

라벨별로는 TF-IDF(통합 OOF 기준)가 이렇다. 파인튜닝이 **같은 자리에서 막히는지**가 핵심이다.

| 라벨 | TF-IDF F1 |
|---|---:|
| 통상수용 | 0.795 |
| 견적반영 | 0.545 |
| 계약·질의검토 | 0.573 |

**판정 기준은 미리 정해져 있다 — 10 fold 중 8 우세.** 평균 차이만 보고 효과라고 부르지
않는다. 문서가 10개뿐이라 fold 분산이 크기 때문이다(2026-08-23 결정).

읽는 요령:

- **1·2·3의 편차** — 셋이 0.59~0.62쯤에 몰리면 "TF-IDF와 차이 없음"이 안전한 결론이다.
  0.58~0.65처럼 벌어지면 seed 하나로 뭔가를 주장할 수 없다는 뜻이고, 그것도 결과다.
- **4 대 1** — 같은 모델·같은 seed·입력만 다르다. 마스킹이 +0.018 근처를 재현하면
  2026-09-02 14:04 결정의 확인 조건이 성립한다. 재현되지 않으면 TF-IDF 특유의 우연이었다.
- **5·6** — large가 base보다 낮으면 "용량이 크면 노이즈 라벨을 더 외운다"는 문헌 관측이
  우리 데이터에서 확인된 것이다. 그게 나오면 오히려 재미있는 결과다.
- **낮은 숫자를 실패로 읽지 말 것.** 로드맵 §9는 "복잡하게 만든 값을 했는가"에 답하는
  설계다. E5·의존구문·앙상블에 이어 파인튜닝까지 TF-IDF를 못 넘으면, 네 갈래로 확인된
  결론이 된다.
