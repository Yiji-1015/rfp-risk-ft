## 2026-08-23 · 평가 설계

**fold 분할 확정** — 문서 단위 **LODO 10겹**, fold마다 학습 8 / 검증 1 / 평가 1 문서.

문서가 10개뿐이라 8:2로 나누면 평가에 2문서만 오르는데, fold 기준선이 34.3%(defense)부터
79.2%(koen)까지 벌어져 있다. 쉬운 두 문서가 걸리면 같은 모델이 두 배 가까운 점수를 낸다.
즉 8:2의 점수는 모델보다 **어느 문서가 걸렸는가**를 더 많이 반영한다.

검증 문서는 **회전**으로 정한다. 파인튜닝은 멈출 시점을 골라야 하는데(§9.4), 평가 문서를
보고 고르면 그 문서는 더 이상 처음 보는 문서가 아니다. 그렇다고 한 문서를 고정해서 쓰면
그 난이도가 모든 fold의 조기 종료 시점에 같은 방향으로 스며든다. 한 칸씩 밀면 모든 문서가
검증도 한 번씩 맡아 편향이 상쇄되고, 무작위가 아니라 seed 없이 재현된다.

**기준선이 둘이었다.** issues/003이 "fold별 다수 클래스 기준선을 병기하라"고 했는데,
계산해보니 그 문장이 가리키는 값이 두 개였다.

- **Dummy** — 학습 집합의 최빈을 찍는다. 배포 가능한 진짜 모델(§9.2)
- **oracle** — 평가 문서 안에서의 최빈. 정답을 본 값이라 배포 불가. fold 난이도의 눈금

이 데이터에서 학습 최빈은 늘 `통상수용`인데 **문서별 최빈은 다르다.** 앵커 제외 후
ccrs·genai는 `견적반영`이 최빈이라 2개 fold에서 Dummy가 oracle보다 낮다.
합쳐서 보고하면 모델이 기준선을 넘었는지가 흐려진다.

**새로 관측한 것 — 003과 006은 독립이 아니다.** 두 이슈를 서로 다른 보고 문제로 적어뒀는데,
실제 학습 8문서 기준으로 나란히 놓으니 **같은 방향으로 정렬돼 있었다(r = 0.635).**
어려운 defense·ccrs·genai는 반복 노출이 4.5 / 0.0 / 0.0%이고, 쉬운 koen·mfds는
20.0 / 23.8%다.

원인을 생각하면 놀랍지 않다 — 인프라 증설 사업은 표준 문구가 많고 그래서 통상수용도 많다.
같은 원인이 두 지표에 나타난 것이다. 다만 이슈 문서 두 개가 그 연결을 적어두지 않아
독립인 것처럼 읽혔다. fold 점수에는 두 값을 항상 함께 적는다.

산출물은 `scripts/evaluation/`(fold 생성·진단, 반복 문구 측정)과 `tests/test_folds.py`다.
반복 문구 계산은 노트북 06 안에만 있던 것을 모듈로 뺐고, 결정 34의 실측값(12.0%, 중앙값
0.209)을 테스트로 고정했다.

**기준선 비교 착수** — TF-IDF + 선형 모델. 파인튜닝은 로드맵에 두고 착수만 미뤘다.

| 설정 | macro F1 | 정확도 | 계약recall |
|---|---:|---:|---:|
| Dummy | 0.219 | 0.506 | **0.000** |
| word 1-2gram + balanced | 0.581 | 0.639 | 0.507 |
| char 3-4gram, weight 없음 | 0.520 | 0.629 | 0.346 |
| **char 3-4gram + balanced** | **0.601** | 0.664 | 0.514 |

Dummy가 정확도 0.491을 내면서 `계약·질의검토` recall은 0.000이다. 세 클래스 중 둘을 아예
예측하지 않기 때문이다. §11.9가 경고한 "정확도가 높아도 중요한 조항을 놓친다"가 첫 실행에서
바로 나왔다.

**효과와 잡음을 가르는 법을 정했다.** 문서가 10개뿐이라 fold 분산이 커서, 평균만 보면
잡음을 효과로 착각한다.

- `class_weight` 없음 → balanced: 평균 **+0.080**, 9/10 우세 → **효과.** 기본값 확정
- 학습 문서 8 → 9: 평균 **+0.001**, 방향도 일정하지 않음 → **잡음**
- 표현 word → char: 평균 +0.020, 편차 폭 0.205 → **판정 보류**

크기 차이가 약 80배다. 어느 파라미터를 먼저 만질지는 이 비교로 정한다. 그리드서치로 한 번에
돌렸다면 이 순서가 안 보였을 것이다.

**틀린 예측 하나를 기록했다.** 분포가 쏠린 fold에서는 balanced가 손해일 거라고 봤는데,
방향은 맞았지만 크기가 틀려서 결론이 반대였다. 균등한 fold에서 balanced가 버는 폭이
훨씬 컸다. 그럴듯한 추론이 6초짜리 실험보다 못했다.

**불균형이 아니라 분포 이동이 문제였다.** 전체 라벨은 50/24/26으로 2.12배라 심한 불균형이
아니다. 진짜 문제는 fold마다 학습 분포와 평가 분포가 최대 34%p 어긋난다는 것이다.
`class_weight`는 불균형은 보정해도 분포 이동은 못 고친다. mfds에서 `견적반영` F1이
0.196이었던 게 이 예다 — 개수는 맞췄는데(예측 26 / 정답 25) 어느 것인지를 못 맞혔다.

**세 갈래 점수를 처음 적용했다**(결정 34). mfds는 반복 문구에서 1.000, 나머지에서 0.460이다.
전체 0.506만 보고 "처음 보는 RFP에 일반화된다"고 하면 주장이 실제보다 강해 보인다.
다만 반복 부분집합이 0~43건으로 흔들려서 건수를 항상 함께 낸다.

산출물은 `scripts/evaluation/baselines.py`, `notebooks/07_baseline_comparison.ipynb`,

## 2026-08-25 · LinearSVC와 검토 가중치 비교

같은 문자 3~4gram TF-IDF에서 분류기만 Logistic에서 LinearSVC로 바꿨다. macro F1은
0.601 → 0.579, `계약·질의검토` recall은 0.514 → 0.494였다. fold별 macro F1 차이는
-0.145~+0.109이고 SVC가 이긴 fold는 4/10이라 개선이 아니다.

LinearSVC의 fold별 학습 분포에서 `balanced` 가중치를 계산한 뒤 검토 클래스만
`1.0 / 1.25 / 1.5 / 2.0배` 후보로 두었다. 평가 문서는 보지 않고 회전 검증 문서의 계약
F2로 골랐다. 선택 결과는 1.0이 4개, 1.25가 0개, 1.5가 2개, 2.0이 4개 fold였다.

검토 가중치 선택은 recall을 0.494 → 0.509로 0.015 올렸지만 precision은 0.607 → 0.597,
macro F1은 0.579 → 0.576으로 내렸다. recall이 오른 fold도 3/10뿐이라 효과로 보지 않는다.
현재 주 기준선은 문자 3~4gram + balanced Logistic(macro F1 0.601)이다.

## 2026-08-25 · 문자+단어 결합과 ComplementNB

단어 1~2gram과 문자 3~4gram을 결합한 balanced Logistic은 macro F1 0.603, 정확도
0.666, 계약 recall 0.532였다. 문자 단독 Logistic보다 macro F1은 +0.003이지만 fold별
차이가 -0.050~+0.067이고 우세가 5/10이라 개선이 아니라 잡음이다.

같은 결합 TF-IDF의 ComplementNB는 macro F1 0.505, 계약 recall 0.351로 명확히 낮았다.
평균 최고 숫자만 따라 모델을 교체하지 않고, 주 기준선은 단순한 문자 TF-IDF balanced
Logistic 0.601을 유지한다. 요구사항 유형 결합 2종도 기준선을 넘지 못했다. 전체 12종
비교는 `notebooks/09_model_summary.ipynb`에 있다.

### 1. ML 비교 이어가기 — §9 · 바로 다음

```
DummyClassifier → TF-IDF + Logistic/SVM → 사전학습 임베딩 + ML → 경량 인코더 파인튜닝
   [완료]                 [완료]                 [완료]              [미룸]
```

각 단계는 "복잡하게 만든 값을 했는가"에 답한다. TF-IDF가 파인튜닝과 비슷하게 나오면
"이 문제엔 TF-IDF로 충분하다"가 결론이고, 그것도 유효한 결과다.

동결 `multilingual-e5-small` 비교 결과는 Logistic macro F1 0.544, LinearSVC 0.546으로,
문자 TF-IDF Logistic 0.601을 넘지 못했다. 입력 표현만 바꾼 결과이며 파인튜닝은 아니다.

남은 것 — 하이퍼파라미터(`C`, `min_df`, `ngram_range`) 선택.
하이퍼파라미터를 고르기 시작하면 **선택을 어디서 할지**를 먼저 정해야 한다. 검증 문서
하나(49~192건)는 선택 신호로 흔들리므로 학습 8문서 안의 inner LODO를 검토한다(§14의 열린 질문).

### 2. 선결 결정

- **파인튜닝 타깃 범위** — 주 라벨 하나만 vs 다중 헤드로 보조 축까지.
  §12가 "처음부터 다중 과제 파인튜닝"을 제외 범위로 두고 있어 §12 수정 여부가 먼저다.
- **어떤 경량 한국어 인코더** — §14의 열린 질문. GPU 예산 약 5천 원 제약이 있다.
