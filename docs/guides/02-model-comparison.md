# 가이드 02 — 무엇을 더해봤고, 왜 대부분 채택하지 않았는가

> 학습용 요약본이다. 시간순 기록은 [`../history/`](../history/)와 [`../WORKLOG.md`](../WORKLOG.md)에,
> 실행 절차는 [`../PIPELINE.md`](../PIPELINE.md)에 있다. **숫자가 어긋나면 그쪽이 정본이다.**
>
> [가이드 01](01-dataset-and-metrics.md)이 "데이터셋이 어떻게 만들어졌고 무엇을 봐야 하는가"라면,
> 이 문서는 **"모델을 어떻게 비교하는가"**다. 01의 §2·§3(LODO, 기준선, macro F1)을 읽었다고 전제한다.

## 0. 이 가이드가 답하는 것

기준선 `char 3-4gram + balanced Logistic`이 macro F1 **0.601**에 도달한 뒤,
2026-08-25 하루 동안 **16가지 변형**을 통제 비교했다. 결과부터 말하면 이렇다.

> **16개 중 채택한 것은 0개다.**

이 가이드는 그게 실패의 기록이 아니라 **§9.3이 물으라고 한 질문에 대한 답**이라는 것을
설명한다. 질문은 처음부터 "최고 점수가 몇 점인가"가 아니라
**"복잡하게 만든 값을 했는가"**였다.

## 1. 선택을 어디서 하는가 — 선택 누수

가이드 01 §2-1이 검증 문서가 왜 따로 필요한지 말했다. 이 가이드의 실험 대부분은
**고를 것이 생긴 실험**이라 그 원칙이 실제로 작동한 첫 사례들이다.

### 1-1. 문제 — 블록 가중치

TF-IDF에 다른 특징 블록(유형 one-hot, 임베딩, 숫자)을 붙이면 **두 블록의 세기를
맞춰야 한다.** 유형 블록을 가중치 1로 그냥 붙였더니 유형 결정 점수의 RMS가 본문보다
평균 **1.327배** 컸다. 즉 불안정한 유형 신호가 본문을 덮고 있었다.

그러면 가중치를 고르면 되는데 — **어디서 고를 것인가?**

```
평가 문서에서 고른다  ->  그 문서는 더 이상 "처음 보는 문서"가 아니다  (선택 누수)
전체에서 고른다       ->  마찬가지
```

### 1-2. 절차

```
fold i 마다:
  후보 0 / 0.05 / 0.1 / 0.25 / 0.5 / 1.0 을
  학습 8문서로 학습 -> 검증 1문서의 macro F1으로 선택
  동률이면 더 작은 가중치
  평가 문서는 선택에 쓰지 않는다
```

**fold마다 다른 값이 뽑힌다.** 그게 정상이다. 유형 블록에서 선택된 가중치 분포다.

| 가중치 | 0 | 0.05 | 0.1 | 0.25 | 1.0 |
|---|---:|---:|---:|---:|---:|
| fold 수 | 3 | 3 | 2 | 1 | 1 |

**배울 점: 선택 결과가 fold마다 흩어진다는 것 자체가 정보다.** 3개 fold가 "0"을
골랐다는 건 그 문서들에서는 유형을 아예 안 쓰는 게 최선이었다는 뜻이다.
검증 문서 하나(37~181건)에서 추정한 값이 다음 문서로 일반화되지 않는다는 신호다.

⚠️ 이건 **하이퍼파라미터 선택 문제 전체를 푼 게 아니다.** `C`, `min_df`, `ngram_range`는
아직 고정값이고, 그것까지 고르려면 학습 8문서 안에서 다시 나누는 **inner LODO**가 필요하다.
검증 문서 하나로는 선택 신호가 흔들린다.

### 읽는 법 — `우세 n/10`과 편차 폭

가이드 01 §3-5의 기준을 그대로 쓴다. **평균만 보면 안 된다.**

- **`우세 5/10`** = 이 변형이 기준선보다 나은 평가 문서가 10개 중 5개.
  나머지는 4개 열세 + 1개 동점이다.
- **`-0.050~+0.067`** = 문서마다 계산한 `변형 - 기준선`의 최소·최대.
  개선과 악화가 **둘 다** 나타났다는 뜻이고, 흔들림 폭은 0.117이다.

1번(word+char)이 평균 0.603으로 관측 최고점 중 하나인데도 **잡음**으로 판정한 이유가
이것이다. 상승폭 +0.003이 흔들림 폭 0.117의 **2.6%**다.

## 3. 왜 최고 점수를 채택하지 않는가

표에서 가장 높은 건 2번 `TF-IDF + E5`의 **0.611**이다. 기준선보다 +0.010이다.
그런데 채택하지 않고 **"유망 후보"로만 남겼다.**

```
평균 상승      +0.010
편차 폭         0.074   (-0.029 ~ +0.045)
우세            5/10
```

상승폭이 흔들림 폭의 **14%**고, 우세가 절반이다. **절반의 문서에서는 오히려 나빠진다.**
처음 보는 RFP에서도 반복될 개선이라고 말할 근거가 못 된다.

> **배울 점: 평균 최고점은 "관측된 최고점"이지 "더 나은 모델"이 아니다.**
> 재현되는 이득이 확인될 때까지 더 단순한 쪽을 유지한다.

이건 겸손이 아니라 **§9.3의 통제 비교 규칙**이다. 복잡한 모델을 채택하려면
"복잡하게 만든 값을 했다"를 보여야 하는데, 0.601 → 0.611은 그걸 못 보인다.

### 반대 방향의 사례 — 채택한 것

같은 기준으로 **채택한** 것도 있다. 가이드 01 §3-5의 `class_weight`다.

| | 평균 | 편차 폭 | 상승/폭 | 우세 |
|---|---:|---:|---:|---:|
| `class_weight` → balanced | +0.080 | 0.254 | **31%** | 9/10 |
| TF-IDF + E5 | +0.010 | 0.074 | 14% | 5/10 |
| word+char 결합 | +0.003 | 0.117 | 2.6% | 5/10 |

**같은 잣대로 재면 세 개가 확실히 다르게 보인다.** 기준이 있으니 "이건 되고 저건 안 된다"를
매번 새로 논쟁하지 않아도 된다.

## 4. 사전학습 임베딩 — 기대와 결과

가이드 01이 "다음 가이드에서 다룰 것"으로 예고한 항목이다.

### 4-1. 왜 기대했나

이슈 008이 말하듯 문자 n-gram은 **어휘가 겹쳐야** 유사성을 잡는다. 그런데 기능 요구사항
202건의 문서 간 재출현률이 **0.0%**다. 기관마다 업무 어휘가 달라 겹치는 게 아예 없다.
의미 표현이면 잡을 수 있지 않겠나 — 이게 가설이었다.

### 4-2. 설정

```
multilingual-e5-small  (인코더 동결, revision 고정)
요구사항 원문에 "query: " 접두사
384차원 평균 풀링 + L2 정규화
같은 8/1/1 LODO, 같은 라벨, balanced 가중치
```

**분류기와 평가 조건을 그대로 두고 입력 표현만 바꿨다.** §9.3의 통제 비교를 지키는 방식이다.

> 임베딩은 **행별 독립 변환**이고 프로젝트 라벨을 보지 않는다. 그래서 분할 전에 한 번
> 생성해도 평가 누수가 아니다. 학습 fold의 통계를 쓰는 표준화와는 성격이 다르다.

### 4-3. 결과 — 가설이 틀렸다

| | macro F1 | 계약 recall |
|---|---:|---:|
| char TF-IDF | **0.601** | **0.514** |
| E5 Logistic | 0.544 | 0.443 |
| E5 LinearSVC | 0.546 | 0.425 |

macro F1 -0.057, 우세 **2/10**. 계약 recall도 -0.071로 같이 내려간다.
편차 폭이 **-0.318~+0.068**로 유난히 넓은 것도 눈에 띈다. 어떤 문서에서는 처참하다.

**결합했을 때만 조금 올랐다**(0.611, §3). 즉 E5가 문자 TF-IDF를 **대체**하지는 못하고,
**보완**은 약하게 할지도 모른다는 정도다.

**배울 점: "원리적으로 못 잡는다"가 "다른 방법이 잡는다"를 뜻하지 않는다.**
문자 n-gram의 한계를 정확히 진단한 것과, 그 한계를 메울 대안을 찾은 것은 별개다.

## 5. 특징을 더하는 것이 왜 대체로 손해였나

5·6·7·8·11번(유형, 글자 수, 숫자)이 전부 마이너스다. 하나씩 보면 이유가 다르다.

### 5-1. 요구사항 유형 — 문서와 얽혀 있다

정본 12종으로 정규화한 유형(가이드 01 §1-5)을 one-hot으로 붙였다. 유형별 통상수용
비율이 1.3%~76.2%로 단조 정렬되니 신호가 있어 보였다.

그런데 **처음 보는 문서에서 불안정한 힌트가 된다.** 유형은 문서별 라벨 분포와 얽혀 있고
(이슈 001), 어떤 유형은 6개 문서에만 나타난다. 가중치를 fold별로 골라 과대 영향을
완화해도(0.549 → 0.589) 기준선을 넘지 못했다.

> **분석 메타데이터로는 유지하되 모델 입력에서는 제외한다.**
> 이건 이슈 목록의 "분석·층화용으로만 필요" 칸(001, 002)이 실측으로 확인된 것이다.

### 5-2. 숫자 정보 — 여러 문서에서 조금씩, 한 문서에서 크게

`log(1+숫자 개수)`와 숫자 유무를 넣었다. 정량 조건의 밀도를 잡으려는 의도였다.

```
평균 -0.009,  우세 6/10,  편차 -0.098 ~ +0.047
```

**우세가 6/10인데 평균이 마이너스다.** 여러 문서에서 소폭 이득이 있지만 일부 문서의
큰 하락을 상쇄하지 못한다는 뜻이다. 우세만 보면 채택할 뻔한 사례다.

⚠️ **집계 버그를 한 번 잡았다.** 줄 시작의 `1)`, `2.`뿐 아니라 표 행 번호(`1 |`)도
숫자로 세고 있었다. 16개 요구사항에서 **문서 서식이 숫자 feature에 섞였다.**
보정 후 6종을 재실행했고 결론은 같았다. 앞선 기록은 지우지 않고 보존한다.

### 5-3. 넣지 않기로 한 것들

목록 개수, 단위 표현, 기준 표현은 아예 시도하지 않았다. **문서 서식을 그대로 반영하거나
표준 문구 반복(이슈 006)과 겹칠 위험**이 커서다. 실험할 수 있다고 다 실험하지 않는다.

## 6. 분류기를 바꾸면 어떤가

### 6-1. 희소 선택과 비선형

선형 모델에서 손해였던 구조·수치 정보가 **다른 계열에서는 유효할 수도** 있다는 가설로
셋을 비교했다.

| | macro F1 | 우세 |
|---|---:|---:|
| char TF-IDF Logistic (기준선) | **0.601** | — |
| SVD100 + XGBoost | 0.564 | 3/10 |
| SVD100 + Logistic | 0.528 | 1/10 |
| Elastic-net Logistic | 0.471 | **0/10** |

**SVD+Logistic을 같이 둔 것이 핵심이다.** XGBoost만 돌렸으면 "비선형이 안 통한다"로
읽었을 텐데, 대조군이 있으니 다르게 읽힌다.

```
SVD+XGBoost  0.564
SVD+Logistic 0.528     차이 +0.036  <- 비선형 결합은 실제로 회복시켰다
기준선       0.601      차이 -0.037  <- 그런데 SVD 압축 손실을 못 메웠다
```

즉 **범인은 분류기가 아니라 SVD 100차원 압축**이다. 희소한 문자 단서가 그 과정에서
날아간다. 대조군 하나가 원인을 바꿔놓았다.

**배울 점: 두 가지를 동시에 바꿨으면 대조군을 하나 더 둔다.** "SVD"와 "XGBoost"를
같이 바꿔놓고 결과가 나쁘면 어느 쪽 탓인지 알 수 없다.

Elastic-net이 **0/10**으로 가장 나쁜 것도 같은 방향이다. L1이 희소 문자 특징을
쳐내는데, 이 데이터에서는 그 희소함이 곧 신호다.

### 6-2. LinearSVC와 계약 클래스 가중치

`계약·질의검토` recall을 올리려고 그 클래스만 가중치를 1.0/1.25/1.5/2.0배로 두고
fold별 검증 문서에서 **계약 F2**(recall에 두 배 무게)로 골랐다.

결과: 기본 SVC 대비 recall +0.013인데 **오른 fold가 3/10뿐**이고 macro F1은 -0.003이다.
효과로 보지 않는다.

⚠️ 이 실험의 수치는 앵커 제외 이전(1,024건) 기준이라 §2 표에 넣지 않았다.
결론을 바꿀 만한 차이는 아니지만 **모집단이 다르면 나란히 놓지 않는다.**

## 7. 새로 생긴 원칙 — 귀무기대와 대조한다

가이드 01 §4의 원칙 넷에 하나가 추가됐다. 2026-08-26의 정정에서 나왔다.

### 무슨 일이 있었나

"평가 문서의 앵커가 학습 문서 라벨 생성에 관여한 비율"을 세었더니 fold마다
**16.5%~44.1%**로 2.7배 차이가 났다. fold별 교란으로 보고 이슈로 등록했다.

그런데 **층화 인출이 기계적으로 만들어내는 값**을 계산하지 않았다. 풀이 라벨별
44/25/31건이고 문서당 앵커가 7~13건이니, 라벨마다 1건씩 뽑을 때 D의 앵커가 들어갈
확률은 그 자체로 계산된다.

| | 최소 | 최대 |
|---|---:|---:|
| 관측 | 16.5% | 44.1% |
| **귀무기대** | **25.0%** | **43.0%** |
| 비 (관측/기대) | 0.57x | 1.53x |

**기대값 자체가 그만큼 벌어져 있었다.** 관측 편차의 대부분이 설계의 구조에서 나온다.
이슈는 철회했다.

### 원칙

> **⑤ fold별 편차를 보고하기 전에, 그 편차가 설계에서 구조적으로 나오는 폭을 먼저 계산한다.**

가이드 01 §4-④("관측과 해석을 분리한다")의 구체판이다. 관측은 옳았고 이름이 틀렸다.
결정 34가 "누수"를 철회했을 때와 같은 실수를, 그 사례를 인용하면서 반복했다.

### 함께 배운 것 — 무엇이 이슈가 아닌가

앵커가 라벨 생성에 관여하는 것은 **의도된 설계**다(결정 9·13·14·18). 결정 10이
차단하기로 한 것은 "타깃과 같은 문서의 앵커" 하나이고 그건 위반 0건으로 지켜졌다.
`AGENTS.md`에 이슈로 적기 전 확인할 네 가지를 넣은 이유다.

```
1. 이미 고쳐졌나          (결정 기록과 코드를 먼저 검색)
2. 의도된 건가            (설계의 미래 계획과 지금 데이터의 차이는 트레이드오프)
3. 귀무기대는 얼마인가     (구조적으로 나오는 폭과 대조)
4. 답이 뭔가를 바꾸는가    (동결된 데이터에서 못 바꾸면 기록이지 작업이 아니다)
```

## 8. 지금 상태

| 설정 | macro F1 | 정확도 | 계약 recall |
|---|---:|---:|---:|
| Dummy | 0.219 | 0.506 | 0.000 |
| **char 3-4gram + balanced Logistic** | **0.601** | 0.664 | 0.514 |
| TF-IDF + E5 (유망 후보) | 0.611 | 0.673 | 0.508 |

**기준선은 여전히 문자 TF-IDF다.** 16가지를 시도해서 이긴 것이 없다.

### 이게 왜 결과인가

§9.3의 사다리는 이렇게 생겼다.

```
Dummy  ->  TF-IDF + 선형  ->  사전학습 임베딩 + ML  ->  경량 인코더 파인튜닝
[완료]        [완료]              [완료 — 못 이김]           [남음]
```

각 칸은 "복잡하게 만든 값을 했는가"에 답한다. 세 번째 칸에서 **못 이겼다는 것 자체가 답**이다.
파인튜닝이 이기면 "이 문제는 의미 표현이 필요하다"가 결론이고, 못 이기면
**"이 문제엔 TF-IDF로 충분하다"가 결론**이다. 둘 다 유효하다.

### 남은 것

| 항목 | 상태 |
|---|---|
| 하이퍼파라미터 (`C`, `min_df`, `ngram_range`) | 고정값. inner LODO 설계 필요 |
| 파인튜닝 타깃 범위 | 주 라벨만 vs 보조 축까지 → §12 수정 여부가 먼저 |
| 어떤 경량 한국어 인코더 | 미정. GPU 예산 약 5천 원 |
| 오류 분석 — `견적반영` | 미착수 (아래) |
| 무작위 few-shot 비교 (§8.2) | 미착수. 층화와 비슷하면 인출기를 유지할 이유가 없다 |

### 오류 분석이 남은 이유

`견적반영`이 계속 가장 안 잡힌다. mfds에서 F1 0.196이었을 때 **예측 개수는 거의
맞췄는데(예측 26 / 정답 25) 어느 것인지를 못 맞혔다.** 소수라서 무시당한 게 아니라
**구분이 안 되는 것**이다(가이드 01 부록).

그럴듯한 이유는 있다 — `견적반영`은 "원가는 붙지만 계산 가능"이라 두 라벨 사이에 낀
중간 범주다. 문자 n-gram이 잡기 가장 어려운 경계다. 다만 이건 아직 **가설이고,
오류 분석으로 확인하지 않았다.**
